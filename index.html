MDTT Testbed

ISO/TS 9241-411 B.6.2.2 Companion tool for “Designing and Reporting Multi-Directional Tapping Tasks: A Systematic Review, Practical Guidelines, and a Configurable Testbed”. Panels R1–R5 configure the task; R6 is covered by the Results and Report tabs.
R1 Apparatus & mapping

R1 Report the interaction apparatus and mapping, rather than only the device name.

The same device can implement direct touch, ray casting, hand, head or gaze selection, so the device name alone does not say what movement was measured. This tool runs a pointer-based task in the browser; for XR, document the chain you implement on your own platform — the exported spec stays valid.

R3 Target geometry

R3 Prefer direction-invariant targets for general comparison, and define width explicitly for other shapes.

Spheres sit on a fronto-parallel circle at this depth. θ = 2·arctan(W / 2z), so a fixed physical width shrinks visually as depth grows — report size, depth and angle together.

Circles and spheres keep W constant across approach directions — the default for general comparison. Shape is not cosmetic: it can change measured movement time.

R4 Count, sequence & trials

R4 Treat target count, sequence, and analysed movements as part of the task definition.

Reported counts run 5–36, most often 13 or 9, and count affects throughput. What defines the task is the count, the sequence rule and the movements actually analysed.

R5 Feedback

R5 Specify feedback states explicitly and keep non-manipulated feedback consistent.

A coloured outline on the target just selected; 0 turns the marker off. The next target is cued at the moment of selection, so the marker never delays a movement or enters its movement time.

Hover and error highlighting measurably shift throughput and error rate — hold every state constant unless feedback is your independent variable, and describe all of them.

OPT Directional sampling

Off by default. Enable only when directional generalisability is central to the question — the trial budget above updates immediately.

06 Pilot run

The task opens full-window. Click the highlighted target to start each sequence, then keep selecting the highlighted target. Press Esc to abort — data collected so far is kept.

07 What gets recorded

The next target is cued at the moment of selection, so outcome feedback never delays a movement or enters its movement time. One row per target-to-target movement: condition, sequence and movement index, direction and phase, the from-point (previous selection point), target centre, first-click endpoint, movement time, hit/miss, attempts, and the practice flag. Effective measures are computed from the first click of every movement, so misses stay in the endpoint distribution as Fitts’ law methodology requires.
